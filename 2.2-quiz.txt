Question #1
Inspect (do not compile) each of the following programs. Determine what the program will output, or whether the program will generate a compiler error.

Assume you have “treat warnings as errors” turned off.

1a)
#include <iostream>

int return7()
{
    return 7;
}

int return9()
{
    return 9;
}

int main()
{
    std::cout << return7() + return9() << '\n';

    return 0;
}


Answer: 16


1b)
#include <iostream>

int return7()
{
    return 7;

    int return9()
    {
        return 9;
    }
}

int main()
{
    std::cout << return7() + return9() << '\n';

    return 0;
}

Answer: Compile error, nested functions are not allowed.


1c)
#include <iostream>

int return7()
{
    return 7;
}

int return9()
{
    return 9;
}

int main()
{
    return7();
    return9();

    return 0;
}

Answer: Nothing will be printed, return values are discarded.


1d)
#include <iostream>

int getNumbers()
{
    return 5;
    return 7;
}

int main()
{
    std::cout << getNumbers() << '\n';
    std::cout << getNumbers() << '\n';

    return 0;
}

Answer: 5 gets printed two times. `return 7;` is unreachable code.


1e)
#include <iostream>

int return 5()
{
    return 5;
}

int main()
{
    std::cout << return 5() << '\n';

    return 0;
}

Answer: Compilation error. Found keyword return when identifier was expected.


Question #2
What does “DRY” stand for, and why is it a useful practice to follow?

Answer: DRY stands for Don't Repeat Yourself. It's a guideline so that we don't
repeat code unnecessarily and refactor multiple instances of the same piece of
code into a function. Eliminate redundancy, improve maintainability and remove
error prone code.
